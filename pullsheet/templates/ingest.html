The scheduled drop — how this normally works

Your inventory system writes its nightly export to the SFTP folder (data/watched/ in this build). It is picked up within a couple of seconds, matched, and finalized into a run, and the file moves to data/archive/. A file that could not be read stays put so you can see it, and the refusal is recorded as a run rather than swallowed.

A file is left alone for two seconds after its last write, so a half-uploaded export is never read as a short one. The same delivery arriving twice is recognised and refused rather than double-counted.

Emailed export

An export mailed as an attachment lands in the same place and becomes the same kind of run, labelled email drop so it is obvious on the run history which channel a day's inventory came in on.

Upload a spreadsheet by hand

For the morning the scheduled drop does not arrive. It produces exactly the same kind of run, labelled spreadsheet upload.
